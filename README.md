# فروشگاه آسترو

فروشگاه اینترنتی فارسی با Django، قالب‌های RTL، حساب کاربری با کد یک‌بارمصرف پیامکی، کاتالوگ، سبد خرید، قیمت‌گذاری سمت سرور، رزرو موجودی، سفارش و پرداخت زرین‌پال.

نام «آسترو» فقط نام پوشهٔ پروژه است؛ نام نمایشی فروشگاه از صفحهٔ مدیریت تنظیم می‌شود. کاتالوگ، اطلاعات تماس و متن سیاست‌ها عمداً با دادهٔ ساختگی پر نشده‌اند.

## اجرای محلی

1. از پوشهٔ ریشهٔ پروژه محیط مجازی را فعال کنید و وابستگی‌ها را نصب کنید:

    .\.venv\Scripts\Activate.ps1
    pip install -r requirements.txt

2. فایل .env.example را به .env کپی کنید و مقدارها را برای محیط محلی تنظیم کنید. در حالت محلی، دیتابیس SQLite پیش‌فرض است.

3. از پوشهٔ astrostore مهاجرت‌ها را اعمال و مدیر اولیه را بسازید:

    cd astrostore
    python manage.py migrate
    python manage.py createsuperuser
    python manage.py runserver

برای اجرای آزمون‌های برنامه:

    python manage.py test account catalog commerce payments storefront

4. برای ورود مشتری، کلید و نام الگوی واقعی Kavenegar لازم است. بدون تنظیم آن، ارسال پیامک انجام نمی‌شود و برنامه ورود موفق را شبیه‌سازی نمی‌کند.

5. برای پرداخت واقعی، شناسهٔ پذیرنده و تنظیمات معتبر زرین‌پال لازم است. درگاه را تا زمان اعتبارسنجی واحد مبلغ و گردش پرداخت با پذیرندهٔ واقعی، در حالت آزمایشی نگه دارید.

مدیریت فروشگاه در /management/ قرار دارد. مدیر اولیه با دسترسی superuser به ابزارها دسترسی دارد؛ برای کارکنان باید مجوزهای جداگانهٔ Django به گروه آن‌ها داده شود.

## ساخت فونت و CSS

در ریشهٔ پروژه اجرا کنید:

    npm install
    npm run build

این کار فونت Vazirmatn را در پوشهٔ static محلی پروژه کپی می‌کند و Tailwind CSS را می‌سازد. ظاهر اصلی نیز با CSS توکنی پروژه پیاده شده است. اگر build در محیطی بدون دسترسی به registry npm اجرا نشود، قالب از فونت‌های محلی سیستم استفاده می‌کند و خروجی Tailwind تولیدشده در صفحه بارگذاری نمی‌شود.

## استقرار و عملیات

پیش از استقرار، راهنمای docs/operations.md و docs/architecture.md را بخوانید. تنظیمات تولیدی باید از متغیرهای محیطی، PostgreSQL، HTTPS، پشتیبان‌گیری مستقل از میزبان، و اجرای منظم مدیریت رزروها و داده‌های OTP استفاده کنند.

## مهارت طراحی

در محیط موجود، دستورالعمل محلی design-system برای توکن‌ها و مستندسازی به‌کار رفت. مهارت UI/UX Pro Max که در پیوند پروژه آمده بود در محیط نصب‌شده وجود نداشت و دریافت CLI آن از npm به‌دلیل دسترسی شبکه فراهم نشد؛ بنابراین ادعا نمی‌شود که خود مهارت اجرا شده است. تصمیم‌های واقعی طراحی در docs/design-system.md ثبت شده‌اند.
